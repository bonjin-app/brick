# 방문자 집계 · 팝업 · 배너

`brick-site` 플러그인. 기존 PHP 게시판에서 코어에 박혀 있던 **접속자 집계**와 **팝업**을
담습니다. 둘 다 없어도 사이트는 돌아가므로 플러그인입니다.

## 시작하기

관리자 → 플러그인에서 **사이트 운영**을 활성화하면 팝업 관리 화면과 블록 세 개가
생깁니다. 방문자 집계는 활성화하는 순간부터 자동으로 셉니다.

페이지 빌더에서 놓을 수 있는 블록:

| 블록 | 쓰는 자리 |
|---|---|
| 접속자 집계 | 푸터에 "오늘 N명 · 어제 N명 · 전체 N명" |
| 배너 | 원하는 자리에 이미지/HTML 배너 |
| 레이어 팝업 | 페이지 위에 떠서 닫을 수 있는 공지 |

레이어 팝업 블록은 **눈에 보이는 것이 없습니다** — 놓아두면 그 페이지에서
조건에 맞는 팝업이 뜹니다. 보통 모든 페이지에 나오는 테마 레이아웃이나
첫 화면에 하나만 놓습니다.

## 방문자 집계

| 지표 | 의미 |
|---|---|
| 오늘 / 어제 | 그 날의 순 방문자 |
| 이번 달 | 이번 달 누적 |
| 전체 | 집계를 시작한 뒤 누적 |
| 최고 | 하루 방문자가 가장 많았던 날과 수 |
| 유입 경로 | 오늘 어디서 들어왔는지 (도메인별) |

같은 사람의 재방문은 **하루에 한 번만** 셉니다. IP와 브라우저(User-Agent)를
함께 보므로, 사무실처럼 IP를 공유하는 환경에서도 사람이 한 명으로 합쳐지지
않습니다.

세지 않는 것:
- 검색 봇 · 모니터링 · curl 등 (`bot|crawl|spider|slurp|curl|wget|headless|monitor|uptime`)
- `/admin` 아래 관리 화면 요청
- 관리자·운영자의 방문 (설정에서 켤 수 있습니다)

### 설계에서 중요한 것

집계는 **조용히 틀리는** 기능입니다. 숫자가 이상해도 아무도 에러를 보지 못합니다.

#### IP를 원문으로 저장하지 않는다

같은 사람인지 판별하는 데 필요한 것은 **동일성**이지 실제 주소가 아닙니다.
그래서 설치마다 다른 소금(salt)을 섞어 해시한 값만 저장합니다.

```
visitor_key = sha256(설치별 소금 | IP | User-Agent)
ip_prefix   = "203.0.*"      -- 대역 통계용
```

- DB가 유출되어도 **접속자 IP 목록이 되지 않습니다.**
- 소금이 설치마다 다르므로 다른 설치본의 기록과 **대조할 수도 없습니다.**
- 유입 경로는 도메인만 남깁니다 — 전체 URL에는 검색어나 세션 토큰이 들어옵니다.

오래된 PHP 게시판은 접속자 IP를 그대로 남깁니다. 접속자 목록 화면이 있어서인데, 그 화면의
가치보다 개인정보 위험이 크다고 판단해 만들지 않았습니다.

#### 날짜는 DB가 정한다

`visit_day` 는 애플리케이션이 계산한 날짜가 아니라 PostgreSQL의 `current_date`
입니다. 서버와 DB의 시간대가 다를 때 자정 무렵에 같은 사람이 두 번 세어지는
것을 막습니다. 해시 키에도 날짜를 섞지 않습니다 — 날짜 구분은 유니크 인덱스
`(visit_day, visitor_key)` 가 합니다.

#### 원본은 하루치만 남긴다

화면에 보이는 것은 일별 합계뿐인데 방문 원본이 영구히 쌓이면 몇 년 뒤 가장 큰
테이블이 됩니다. 그래서 `site_visits` 는 오늘치만 두고(중복 판별용), 날짜가
바뀐 것을 처음 알아챈 요청에서 지난 날짜를 지웁니다.

방문마다 DELETE를 시도하지 않습니다 — 소득 없는 스캔이 매 요청에 붙습니다.
프로세스가 재시작되면 그 뒤 첫 방문에서 한 번 더 도는데, 멱등이므로 결과는 같습니다.

#### 재방문은 INSERT 한 번으로 끝난다

```sql
INSERT INTO site_visits (...) ON CONFLICT (visit_day, visitor_key) DO NOTHING
RETURNING id
```

새 방문일 때만 행이 돌아오고, 그때만 일별 합계를 올립니다. 재방문의 비용은
인덱스 조회 한 번입니다.

#### 집계가 페이지를 늦추지 않는다

코어는 `page.viewed` 훅을 **기다리지 않고** 발행합니다. 집계가 느리다고
페이지가 늦게 뜨면 안 되고, 집계가 실패한다고 페이지가 안 뜨면 더 안 됩니다.
렌더 캐시가 적중한 요청에서도 훅은 발행됩니다 — 캐시된 페이지를 본 것도 방문입니다.

## 팝업 · 배너

같은 테이블·같은 관리 화면을 쓰고 `종류` 로 구분합니다.

| 설정 | 설명 |
|---|---|
| 노출 경로 | `*` = 전체. `/shop` = 쇼핑몰 전체(하위 경로 포함) |
| 노출 기간 | 시작·종료. 비우면 즉시·무기한 |
| 다시 보지 않기 | N일. 0이면 체크박스를 제공하지 않음 |
| 위치·너비 | 레이어 팝업만 |
| 링크 | 클릭 시 이동. 새 창 여부 선택 |

노출 수와 클릭 수가 기록되므로 이벤트 배너의 효과를 볼 수 있습니다.

### 경로 매칭

```
path_prefix = "*"      → 모든 페이지
path_prefix = "/shop"  → /shop, /shop/item-1  (O)
                         /shopping-mall       (X)
```

접두어가 우연히 겹치는 경로에는 뜨지 않습니다. 뒤 슬래시는 저장할 때 지우므로
`/shop` 과 `/shop/` 이 다르게 동작하지 않습니다.

### 설계에서 중요한 것

#### 노출 조건은 서버에서 걸러낸다

기간과 활성 여부를 SQL에서 판단합니다. 클라이언트가 판단하는 방식이면 **아직
시작하지 않은 이벤트 내용이 응답에 실려 나갑니다** — 개발자 도구를 열면 다음 주
세일가가 보입니다.

#### 팝업 본문은 새니타이즈한다

팝업은 관리자만 쓰지만, 운영자 계정이 털렸을 때 **전 방문자에게 스크립트가
배포되는 통로**가 되면 안 됩니다. 그래서 저장 시점에 허용 목록으로 걸러냅니다:

- `script` · `iframe` · `style` · `object` · `embed` · `form` · `svg` 는 내용까지 제거
- `on*` 속성 전부 제거
- `href` · `src` 는 `/` 또는 `http(s)`, `mailto:` 만 허용 (공백·제어문자를 지운 뒤 비교)
- `style` 은 안전한 선언 형태만 (`expression()` · `url()` 차단)
- `a` 에는 `rel="noopener noreferrer"` 강제

게시판의 새니타이저를 재사용하지 않습니다 — 플러그인끼리 코드를 공유하지 않는
것이 배포 단위의 독립성을 지키는 방법이고, 팝업은 게시글보다 훨씬 좁은 태그만
필요하므로 더 엄격한 목록을 따로 둡니다.

#### 팝업은 클라이언트가 가져온다

'다시 보지 않기'는 브라우저만 아는 상태입니다. 서버가 렌더한 HTML에 팝업이
들어 있으면 이미 닫은 사용자에게도 전달되고, 화면을 깜빡이며 지워야 합니다.
그래서 팝업 블록은 껍데기만 내고 목록은 fetch로 가져옵니다.

'다시 보지 않기'는 쿠키가 아니라 `localStorage` 에 만료 시각을 적습니다.
팝업 상태는 서버가 알 필요가 없고, 쿠키는 **모든 요청에** 실려 나갑니다.
시크릿 모드처럼 저장이 막힌 환경에서는 다음에 다시 뜰 뿐, 기능이 깨지지 않습니다.

배너는 반대로 서버 렌더입니다 — 모두에게 같은 내용이고, 검색엔진이 읽어도
문제가 없으며, 캐시에 담겨도 됩니다.

## 설정

| 설정 | 기본값 | 설명 |
|---|---|---|
| 방문자 집계 사용 | 켜짐 | 끄면 더 세지 않습니다 (기존 기록은 유지) |
| 관리자 방문 집계 | 꺼짐 | 자기 사이트를 자기가 새로고침하는 것을 세지 않습니다 |
| 일별 합계 보관 기간 | 무기한 | 일 수를 지정하면 그보다 오래된 합계를 지웁니다 |

## API

모든 경로는 `/api/plugins/brick-site` 아래입니다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/visits` | 공개 집계 (오늘·어제·전체·최고) |
| GET | `/popups?path=&kind=` | 이 경로에 띄울 팝업/배너 |
| POST | `/popups/:id/click` | 클릭 기록 |
| GET | `/admin/visits` | 일별 추이 30일 + 유입 경로 (관리자) |
| GET/POST/PUT/DELETE | `/admin/popups` | 팝업 CRUD (관리자) |
| GET/PUT | `/admin/settings` | 집계 설정 (관리자) |

공개 집계는 **요약만** 냅니다. 일별 추이와 유입 경로는 운영 정보이므로
관리자만 봅니다.

## 아직 없는 것

접속자 실시간 목록(개인정보 위험이 크다고 판단해 만들지 않았습니다),
페이지별 조회 순위, 국가·지역 통계(IP 대역만 저장하므로 별도 DB가 필요합니다),
팝업 A/B 테스트.

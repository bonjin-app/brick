# 회원 단체메일

회원에게 공지나 광고 메일을 보냅니다. **광고 메일은 법적 요건이 있고**,
Brick 은 그 요건을 운영자가 실수로 어길 수 없도록 강제합니다.

관리자 → 회원 → 단체메일.

## 먼저 알아야 하는 것: 공지와 광고는 다른 규칙을 받는다

| | 공지 | 광고 |
|---|---|---|
| 예 | 약관 개정, 서버 점검, 서비스 변경 안내 | 세일, 쿠폰, 신상품, 이벤트 |
| 수신 동의 | 필요 없음 | **동의한 회원에게만** |
| 제목 | 그대로 | **`(광고)` 자동 표기** |
| 수신거부 링크 | 붙지 않음 | **자동 첨부** |

근거는 정보통신망법 제50조입니다. 영리목적 광고성 정보는 사전 동의를 받은
사람에게만 보낼 수 있고, 제목에 `(광고)`를 표기하고 본문에 수신거부 방법을
밝혀야 합니다. **위반하면 3천만원 이하 과태료**입니다.

> **판단이 애매하면 광고로 보내세요.** "쿠폰을 드립니다"는 안내처럼 보이지만
> 광고입니다. 공지로 보내야 할 것을 광고로 보내면 일부가 못 받는 것으로
> 끝나지만, 반대는 위법입니다.

Brick 은 종류를 고르면 나머지를 알아서 맞춥니다. **광고를 동의 없이 보내는
설정은 없습니다** — 체크박스로도 API 로도 표현할 수 없습니다.

## 준비: SMTP 설정

SMTP 를 설정하지 않으면 발송이 **거부됩니다**. 보냈다고 표시되고 아무도
못 받는 것보다 낫기 때문입니다.

```bash
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=noreply@example.com
SMTP_PASS=········
SMTP_FROM=우리사이트 <noreply@example.com>
```

`SMTP_HOST` 를 넣으면 `SMTP_FROM` 은 필수입니다(일부만 설정하면 조용히
실패하므로 시작할 때 알려줍니다). 설정을 바꾸면 서버를 다시 시작하세요.

## 보내기

1. **종류 선택** — 공지 / 광고
2. **대상 조건** (선택) — 아래 참고
3. **미리보기** — 몇 명에게 가는지, 동의하지 않아 빠진 사람이 몇 명인지 확인
4. **작성** — 제목·본문. 광고면 저장할 때 `(광고)`가 붙습니다
5. **발송** — 큐에서 처리됩니다. 창을 닫아도 계속 보냅니다

미리보기를 꼭 보세요. **잘못 보낸 메일은 되돌릴 수 없습니다.** 표본 주소는
`ho***@example.com` 처럼 가려서 보여줍니다.

### 대상 조건

| 조건 | 뜻 |
|---|---|
| 역할 | 일반회원 / 운영자 / 관리자 |
| 가입일 | 이후 / 이전 |
| 장기 미접속 | 지정한 일수 이상 로그인하지 않은 회원 |
| 이메일 인증 | 인증을 마친 회원만 |

조건을 걸지 않으면 전체입니다. 어떤 조건이든 **탈퇴·정지 회원과 이전 과정에서
생성된 가짜 주소(`@*.invalid`)는 항상 제외**됩니다.

조건은 캠페인에 저장됩니다 — 나중에 "누구에게 보냈는가"를 설명할 수 있어야
하기 때문입니다.

### HTML 메일

`HTML 로 작성` 을 켜면 본문을 HTML 로 봅니다. 텍스트 대안이 자동으로 함께
발송됩니다(HTML 만 보내면 스팸 판정을 받습니다).

## 발송 중과 발송 후

수만 명에게 보내는 데는 시간이 걸립니다. 대상은 발송 전에 목록으로
확정되고, 20건씩 나눠 보냅니다.

- **중단** — 발송 중에 멈출 수 있습니다. 이미 보낸 것은 되돌릴 수 없습니다
- **서버가 죽으면** — 다시 시작하면 아직 안 보낸 사람만 보냅니다. 같은
  사람에게 두 번 가지 않습니다
- **결과** — 성공 / 실패 / 건너뜀 건수와 실패 사유를 볼 수 있습니다

### "건너뜀"은 무엇인가

대상을 확정한 뒤 발송되기까지 사이에 회원이 **수신거부를 하면** 건너뜁니다.
목록에 있어도 보내지 않습니다 — 보내면 위법이기 때문입니다. 발송 직전에
동의를 다시 확인합니다.

### 발송 이력은 지워지지 않는다

수신자 주소는 발송 시점의 값을 그대로 복사해 둡니다. 회원이 주소를 바꾸거나
탈퇴해도 "어디로 보냈는가"는 남습니다. 발송 이력은 사실의 기록이자, 분쟁이
생겼을 때의 증거입니다.

## 회원이 수신거부하는 방법

광고 메일 본문에는 이런 안내가 자동으로 붙습니다:

```
─────────────────────────────────────
이 메일은 광고성 정보 수신에 동의하신 분께 발송되었습니다.
수신을 원하지 않으시면 아래 링크를 눌러주세요 (로그인 불필요):
https://example.com/api/mail/unsubscribe?token=…
```

**로그인이 필요하지 않습니다.** 링크 한 번으로 해제됩니다. 토큰은 회원별로
하나이고 만료되지 않으므로, 오래된 메일의 링크도 동작합니다.

회원이 직접 마이페이지에서 켜고 끌 수도 있습니다(회원정보 → 광고성 정보 수신).

## 자주 겪는 상황

**광고 대상이 0명입니다**
가입 시 광고 수신에 동의한 회원이 없습니다. 동의는 소급해서 만들 수 없습니다 —
동의 없이 보내는 것이 위법이므로, "일단 보내고 싫으면 거부하라"는 접근은
쓸 수 없습니다. 서비스 안에서 동의를 받는 화면을 만드세요.

**기존 사이트에서 옮겼는데 동의 정보가 없습니다**
기존 게시판의 메일 수신 설정 값을 광고 수신 동의로 옮깁니다
([이전 문서](migrate-gnuboard.md) 참고). 그 값이 없거나 신뢰할 수 없으면
광고는 새로 동의를 받아야 합니다.

**발송이 실패했습니다**
관리 화면의 실패 사유를 보세요. 대부분 SMTP 설정, 발송 한도 초과,
또는 존재하지 않는 주소입니다. 특정 회원만 실패하면 주소 문제이고,
전원 실패하면 SMTP 문제입니다.

**메일이 스팸함으로 갑니다**
SPF·DKIM 을 설정하세요. 도메인 인증 없이 대량 발송하면 대부분 걸러집니다.
`SMTP_FROM` 의 도메인이 실제 발송 서버와 일치해야 합니다.

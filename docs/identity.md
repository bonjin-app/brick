# 본인인증

성인 상품(주류·성인용품)을 팔려면 청소년보호법상 나이를 확인해야 하고, 커뮤니티는 "한 사람
한 계정" 으로 다중 계정을 막습니다. Brick 은 본인인증 결과를 **코어가 한 곳에** 두고, 인증
공급자(포트원 등)는 플러그인이 등록합니다 — 쇼핑몰과 게시판이 같은 확인을 봅니다.

## 켜는 법 (포트원)

1. [포트원 콘솔](https://admin.portone.io)에 **본인인증 채널**(다날·KCP·이니시스 통합인증)을 추가
2. 관리자 → 플러그인 → **포트원 결제** 활성화
3. 관리자 → **포트원** 에서

| 항목 | 설명 |
|---|---|
| 상점 ID · V2 API 시크릿 | 결제와 같은 값 ([결제 문서](payments.md#포트원-설정--이미-계약한-pg-를-그대로)) |
| 본인인증 사용 | 결제 사용과 **따로** 켠다 — 결제는 다른 PG 로 받고 본인인증만 포트원으로 해도 된다 |
| 본인인증 채널 키 | `channel-key-…`. 결제 채널 키와 다르다 |

켜면 회원이 `/identity` 화면에서 인증할 수 있고, 회원 정보(`/account`)에 본인인증 칸이 생깁니다.

## 무엇이 되나

- **성인 상품** — 상품 편집의 "성인 상품 (19세 이상)". 확인한 성인만 상세를 보고 주문합니다.
  - 목록·관련 상품·기획전·검색에는 **누가 보든** 사진 대신 19 표시가 나갑니다(목록은 캐시되고
    여러 곳이 같은 카드를 그리므로, 확인은 상세에서 한다)
  - 상세는 비회원에게 로그인 → 본인인증으로 돌아오는 길을, 인증하지 않은 회원에게 본인인증
    길을, 인증 결과 19세 미만인 회원에게 볼 수 없다는 안내를 보여줍니다. 상품명도 제목에
    싣지 않습니다
  - 주문·정기배송 가입·정기배송 회차가 서버에서 막힙니다(비회원은 성인으로 확인할 길이 없다)
- **게시판별 요구** — 게시판 설정의 "본인인증 요구"(그누보드의 `bo_use_cert`): 본인인증한 회원만 ·
  성인 인증한 회원만. 목록·글·댓글·첨부·글쓰기가 확인 뒤에만 열리고, 통합검색·사이트맵·RSS·최근 글
  위젯에서는 빠진다. 운영진은 통과한다.
- **회원 본인인증 필수** — 관리자 → 설정 → 회원. 인증하지 않은 회원은 글·댓글·주문·장바구니처럼
  무언가를 남기는 일을 할 수 없고(둘러보기는 막지 않는다), 로그인하면 본인인증 화면으로 안내된다.
  비회원·운영진은 대상이 아니다. **인증 수단이 켜져 있을 때만** 적용된다 — 수단이 없으면 아무도 인증할
  수 없어 전원이 잠기기 때문이다.
- **가입 전 본인인증** — 관리자 → 설정 → 회원. 본인인증을 마친 브라우저만 가입 양식을 보낼 수 있습니다
  (아래 "가입 전 본인인증").
- **한 사람 한 계정** — 관리자 → 설정 → 회원. 같은 사람이 이미 다른 계정에서 인증했으면 두
  번째 계정의 인증을 거절합니다. 인증 자체를 강제하지는 않습니다.
- **플러그인** — `ctx.identity.status(userId)` → `{ verified, adult, verifiedAt }`,
  `ctx.identity.url(next)` → 인증 화면 주소. 공급자는 `ctx.registerIdentityProvider()`.

성인 판정은 청소년보호법의 **연 나이**입니다 — "19세에 도달하는 해의 1월 1일을 맞이한 사람"
부터 성인이므로 생일이 지났는지 보지 않습니다(한국 시간 기준).

## 관리자 → 본인인증 (어디서 받고 얼마나 쓰나)

본인인증을 요구하는 곳은 흩어져 있습니다(사이트 설정의 셋, 쇼핑몰의 성인 상품, 게시판마다의 요구). 이 화면이
한곳에 모아 보여 줍니다 — 바꾸는 것은 각 제자리에서 하고, 이 화면은 거기로 보냅니다.

- **인증 수단** — 지금 켜져 있는 공급자. 없으면 아래 요구 설정을 켜 두어도 강제되지 않는다는 것을 함께 말합니다.
- **어디서 받나** — 회원 본인인증 필수·가입 전 본인인증·한 사람 한 계정(켜짐/꺼짐), 그리고 확장이 선언한 목적
  (쇼핑몰: 성인 상품 몇 개, 게시판: 본인인증·성인 게시판 몇 개)과 그 관리 화면.
- **최근 30일 사용량** — 인증창을 연 수·성공·실패·끝나지 않음(회원/가입 전 손님), 날마다(사이트 시간대), 인증한 회원 수.
  본인인증은 건당 요금이 나가므로 갑자기 늘면 여기서 보입니다. 가입하지 않은 손님의 인증은 하루 뒤 지워져 빠지고,
  청구 금액은 공급자 콘솔에서 확인합니다.

확장은 `ctx.registerIdentityPurpose({ key, label, summary })` 로 목적을 선언합니다([플러그인 개발](plugin-development.md)).
끄면 걷히고, 한 확장의 요약이 실패해도 그 줄만 "확인할 수 없음" 이 됩니다.

## 가입 전 본인인증

그누보드의 "가입 화면 본인확인" 과 같은 자리입니다. 켜면 가입 양식(`/register`)이 먼저 본인인증으로
안내하고(`/identity?signup=1` — 테마 화면이라 공급자 SDK 가 돈다), 인증을 마치면 양식으로 돌아옵니다.

- **계정을 만들기 전에 거절합니다** — 만 14세 미만(법정대리인 동의 절차가 없다 — 개인정보보호법 제22조의2),
  그리고 "한 사람 한 계정" 을 켠 사이트에서 이미 가입한 사람. 계정을 만든 뒤에 거절하면 빈 계정이 남습니다.
- 만 14세는 **만 나이**(생일이 지나야 한 살)로 봅니다 — 성인 판정의 연 나이와 다릅니다. 생년월일은 판정에만
  쓰고 남기지 않습니다(만 14세 이상인지만 남는다).
- 인증은 회원 대신 **이 브라우저**에 묶입니다 — 서버가 만든 비밀값을 스크립트가 읽을 수 없는 쿠키로 주고,
  다른 브라우저나 회원 인증 경로로는 그 인증을 가져갈 수 없습니다.
- 가입이 인증 결과를 **계정을 만드는 트랜잭션 안에서** 가져갑니다. 한 번만 가져갈 수 있고(쿠키를 복사해 두어도
  두 번째 계정은 안 된다), 가져간 뒤에는 요청에 남았던 사람 해시·출생 연도를 지웁니다. 같은 사람이 두 창에서
  동시에 가입해도 한 사람 한 계정이 지켜집니다(가입할 때 사람 단위로 줄을 세워 다시 본다).
- 인증을 마친 뒤 **30분** 안에 가입해야 합니다. 가입하지 않은 인증은 하루 뒤 지웁니다.
- **소셜 로그인으로 가입하는 길**은 이 양식을 거치지 않으므로, 이 설정을 켜면 인증하지 않은 회원(소셜 가입,
  설정 전에 가입한 회원)은 "회원 본인인증 필수" 와 같이 인증하기 전까지 쓰기가 막히고 로그인하면 인증 화면으로
  갑니다.
- 손님에게 열린 유료 호출이라 인증창 열기는 주소마다 시간당 10번까지이고, **이 설정을 켠 사이트에서만** 열립니다
  (성인 상품용으로만 본인인증을 켠 사이트에서 누구나 손님 인증창을 열어 요금을 쓰게 하지 않는다).

## 무엇을 저장하나

| 저장한다 | 저장하지 않는다 |
|---|---|
| 출생 연도 (성인 판정) | 이름 · 생년월일 · 전화번호 · 성별 |
| CI 의 HMAC (한 사람 판정 — 사이트 비밀로 만든다) | CI · DI 원문 |
| 인증 요청 기록(언제·어느 공급자·성공 여부, 30일 뒤 삭제) | 공급자 응답 원문 |

CI 원문을 두지 않는 이유: 평생 바뀌지 않는 식별자라 새면 되돌릴 수 없고, 같은 사람인지만
알면 되기 때문입니다. **탈퇴하면 인증 결과와 요청 기록을 모두 지웁니다** — 그래서 한 사람 한
계정 사이트에서도 탈퇴 후에는 다시 인증할 수 있습니다(재가입 제한은 개인정보를 남길 근거가
못 된다고 봤습니다).

## 지키는 것

- **인증 ID 는 서버가 만들고 회원에게 묶습니다.** 브라우저가 정한 ID 를 받으면 남이 끝낸
  인증(또는 공급자 콘솔에서 본 ID)을 내 계정에 붙일 수 있습니다. 한 번 쓰면 끝이고 30분이
  지나면 받지 않습니다.
- **결과는 공급자에게 직접 묻습니다.** 화면이 보낸 이름·생년월일은 받지도 않습니다. 상태가
  `VERIFIED` 이고, 상점이 맞고, CI(또는 DI)와 생년월일이 있을 때만 인정합니다.
- **명의는 바뀌지 않습니다.** 이미 인증한 계정을 다른 사람으로 다시 인증하면 거절합니다 —
  바꿔 주면 성인 한 명이 미성년자의 계정마다 인증을 덮어써 줄 수 있습니다.
- **동시에 끝내도 한 계정만.** 같은 사람이 여러 계정에서 같은 순간에 인증을 끝내도 사람 단위로
  줄을 세워 하나만 저장합니다(스모크가 스무 계정을 같은 순간에 보내 확인한다).
- **인증창은 무한히 열 수 없습니다.** 본인인증은 건당 요금이 나가므로 회원당 한 시간에 10번
  (확인 조회는 30번)까지입니다.

## 아직 없는 것

- 공급자 청구 금액 연동 — 사용량(건수)은 보여 주지만 금액은 공급자 콘솔에서 봅니다.
- 포트원 외의 직접 연동(NICE·KCP 단독 계약) — 공급자 계약에 맞춰 플러그인으로 붙인다.
- 실제 포트원 계정으로의 시험 — 스텁 포트원으로 HTTP 경로 전체를 시험했지만, 실제 채널에서
  인증창이 열리는지는 운영 전에 테스트 채널로 확인하세요.

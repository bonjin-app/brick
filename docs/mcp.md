# MCP 서버와 읽기 전용 API 토큰

AI 에이전트(Claude Code·Cursor 등)가 **돌고 있는 사이트를 읽게** 합니다 — 상태, 대시보드 경고, 플러그인, 업데이트, 화면이
그려진 결과. 저장소를 고치는 에이전트를 위한 안내는 [AGENTS.md](../AGENTS.md)에 있습니다.

핵심은 에이전트에게 **좁은 열쇠**를 주는 것입니다. 로그인 세션을 주면 그 세션은 쓰기까지 되는 전체 관리자 권한이라, 에이전트의
설정 파일이 새거나 에이전트가 잘못 움직이면 사이트를 지울 수 있습니다.

## 1. 토큰 만들기 (관리자)

토큰은 로그인 세션으로만 만들고 폐기합니다 — 토큰 자신은 토큰을 만들지도 지우지도 못합니다.

```bash
# 관리자로 로그인한 세션 쿠키(brick_session)로 — 비밀번호를 한 번 더 묻습니다
curl -b cookies.txt -X POST https://내사이트.com/api/admin/api-tokens \
  -H 'content-type: application/json' \
  -d '{"name":"내 에이전트","expiresInDays":30,"password":"관리자 비밀번호"}'
# → {"id":"…","token":"brk_…","expiresAt":"…","paths":[…]}
```

- **원문(`token`)은 이 응답에만 있습니다.** 서버에는 해시만 남으므로 잃어버리면 새로 만들어야 합니다.
- 유효 기간은 1~365일(기본 90일). 사용 중인 토큰은 20개까지.
- `GET /api/admin/api-tokens` 로 목록(이름·끝 네 글자·마지막 사용·만료·폐기)을, `DELETE /api/admin/api-tokens/:id` 로 폐기합니다.
  폐기하면 **다음 요청부터** 거절됩니다. 만든 관리자가 강등·비활성화돼도 토큰이 함께 죽습니다.
- 만들기·폐기는 감사 로그에 남습니다(토큰 원문은 남지 않습니다).

## 2. 토큰으로 되는 것

**읽기(GET)만, 아래 경로만.** 허용목록이라 새 관리 경로가 생겨도 여기에 적지 않으면 토큰으로는 닿지 않습니다.

| 경로 | 무엇 |
|---|---|
| `/healthz` · `/readyz` | 살아 있는가 |
| `/api/admin/version` | Brick 버전 |
| `/api/admin/dashboard` | 설정 경고(메일 미설정·테마 문제·꺼진 플러그인)와 카드 수치 |
| `/api/admin/areas` | 관리 화면 목록 |
| `/api/admin/updates` | 나온 업데이트 |
| `/api/plugins` · `/api/themes` | 설치된 확장 |
| `/api/openapi.json` | API 문서 |
| `/api/render/page?path=` | 서버가 그린 화면(손님 기준) |

**일부러 없는 것**: 회원·주문·문의·알림·내 정보, 감사 로그(행위자 이메일과 IP 가 있습니다), 그리고 모든 쓰기. 토큰이 새도
개인정보는 새지 않고 사이트는 바뀌지 않습니다. 대시보드 응답에 회원 이메일이 섞이지 않는 것도 스모크가 확인합니다.

## 3. MCP 서버

`scripts/brick-mcp.mjs` — 의존성 없는 표준입출력 MCP 서버(Node 20+). 도구는 전부 읽기입니다:

`site_status` · `dashboard` · `list_plugins` · `list_themes` · `check_updates` · `admin_areas` · `render_page` · `api_reference`

```bash
claude mcp add brick \
  -e BRICK_URL=https://내사이트.com \
  -e BRICK_TOKEN=brk_… \
  -- node /경로/scripts/brick-mcp.mjs
```

이제 에이전트에게 "지금 사이트에 설정 경고가 있어?", "게시판 화면이 200으로 나와?", "올릴 업데이트가 있어?" 를 물을 수 있습니다.
토큰이 없거나 폐기·만료됐으면 도구가 프로토콜 오류가 아니라 **이유가 적힌 결과**를 돌려주므로 에이전트가 읽고 스스로 알립니다.

## 4. 이 구조가 막는 것

| 위협 | 막는 방법 |
|---|---|
| 설정 파일이 새서 사이트가 바뀜 | 읽기(GET)만 — 인증 서비스가 한 곳에서 강제하므로 모든 가드가 같은 제한을 받는다 |
| 새서 개인정보를 봄 | 허용목록에 개인정보 경로가 없다 (단위 검사가 정규식으로 지킨다) |
| 토큰이 토큰을 만들어 자리를 지킴 | 토큰 관리 경로는 허용목록 밖 |
| 오래 방치된 열쇠 | 만료(최대 365일) · 폐기 즉시 · 만든 사람이 관리자가 아니면 무효 |
| DB 유출 | 해시(sha256)만 저장. 원문 무작위 192비트 |
| 쿼리·점 경로·접두사 속임수 | 경로는 쿼리를 떼고 정확히 일치할 때만 |

# 로드맵

목표는 하나입니다. **그누보드5 + 영카트5로 하던 일을 Brick에서 다 할 수 있게 하는 것.**

"더 좋은 기술"은 목표가 아닙니다. 그누보드로 사이트를 운영하던 사람이 Brick으로
옮겨왔을 때 *없어서 못 하는 일*이 없어야 합니다. 그래서 이 문서는 자랑이 아니라
**격차 목록**입니다.

## M15 — 회원 생애주기 (법적 필수) ✅ 완료

**왜 최우선인가.** 회원 탈퇴가 없는 사이트는 한국에서 **운영할 수 없습니다.**
정보통신망법은 이용자가 언제든 동의를 철회할 수 있어야 한다고 정하고,
개인정보보호법 제21조는 목적 달성 후 지체 없는 파기를 요구합니다.
가입 시 약관·개인정보 수집 동의도 마찬가지입니다. 이건 기능이 아니라 **전제**입니다.

- **약관 동의** — 이용약관 · 개인정보 수집·이용 동의(필수), 마케팅 수신(선택).
  관리자가 본문을 편집하고, 개정 시 재동의를 받는다. 동의 이력을 남긴다
  (분쟁 시 "동의받았다"를 증명해야 하는 쪽은 사업자다).
- **만 14세 미만 가입 제한** — 법정대리인 동의 절차 없이는 가입을 막는다.
- **이메일 인증** — 가입 후 인증 메일, 미인증 상태의 권한 제한을 관리자가 선택.
- **회원 탈퇴** — 즉시 탈퇴. 개인정보는 파기하고, 전자상거래법상 보존 의무가 있는
  주문·결제 기록은 **작성자를 끊고 남긴다**(5년). 게시글은 남길지 지울지 선택.
- **내 정보 수정** — 비밀번호 변경(현재 비밀번호 확인), 닉네임, 연락처, 수신 동의.
- **휴면 계정** — 장기 미접속 계정 처리. 파기 전 사전 통지.

## M16 — 사이트 운영 기본기

그누보드 사이트가 예외 없이 다 쓰는 것들입니다.

- **1:1 문의** — 비공개 문의 + 관리자 답변. 게시판으로도 되지만, 문의는
  "내 것만 보이는" 것이 기본이어야 하고 답변 알림이 필요하다.
- **FAQ** — 분류 + 항목, 검색.
- **설문조사** — 복수 선택, 기간, 중복 투표 방지(회원/IP 해시), 결과 공개 시점.
- **최신글 모아보기** — 여러 게시판의 최신글을 한 블록에. 그누보드의 `latest()`.
  메인 페이지를 만드는 데 사실상 필수다.
- **회원 메일 발송** — 관리자가 조건으로 회원을 골라 단체 메일. 수신 동의 존중,
  발송 이력.
- **robots.txt · sitemap.xml** — 지금 없다. 검색 노출을 목표로 하면서 사이트맵이
  없는 것은 앞뒤가 맞지 않는다.

## M17 — 쇼핑몰 실무

지금 쇼핑몰은 "팔 수는 있지만 사후 처리를 못 하는" 상태입니다.

- **주문 취소 · 반품 · 교환** — 부분 취소(상품 단위), 금액 재계산, 재고 복원,
  포인트·쿠폰 원복, 부분 환불 연동. 상태 이력.
- **위시리스트 · 최근 본 상품** — 비회원도 되도록(로컬 + 회원 병합).
- **지역별 배송비** — 제주·도서산간 추가 배송비. 우편번호 기준.
- **사업자정보 표기** — 통신판매업 신고번호 · 사업자등록번호 · 대표자 · 주소 ·
  호스팅 제공자. 전자상거래법상 표시 의무. 테마 푸터에 자동 반영.
- **관련 상품 · 함께 구매** — 상품 상세 하단.
- **판매 리포트** — 기간별 · 상품별 · 분류별. 지금 통계는 총액 수준이다.

## M18 — 그누보드에서 옮겨오기

**채택의 실질적 관문.** 아무리 좋아도 10년 쌓인 게시글을 버릴 수는 없습니다.

- MySQL 접속 정보를 받아 회원 · 게시판 · 게시글 · 댓글 · 첨부 · 포인트를 읽어온다.
- 비밀번호는 그누보드 해시(`password_hash` 또는 구형 MD5)를 **그대로 보존**하고,
  첫 로그인 시 검증에 성공하면 argon2로 재해싱한다 — 회원이 비밀번호를 다시
  만들지 않아도 된다.
- 게시판 레벨(1~10)을 Brick의 4단 역할로 어떻게 접는지 미리 보여주고 조정받는다.
- 리허설 모드: 실제로 쓰지 않고 무엇이 몇 건 옮겨지는지, 무엇이 안 옮겨지는지 먼저 보고.

## 의도적으로 안 하는 것

- **워드프레스식 자체 업데이터** — Node는 모듈을 메모리에 유지하므로 파일 부분 교체가
  복구 불가 상태를 만들 수 있다. 원자적 교체(새 디렉터리 → 검증 → 심볼릭 링크 전환)로
  설계하지 않을 거라면 넣지 않는다. ([docs/upgrade.md](upgrade.md))
- **그누보드의 10단 회원 레벨** — 플러그인끼리 레벨 숫자의 의미를 합의할 수 없다.
  4단 역할(guest/member/manager/admin)로 접는다. (ADR-25)
- **순수 PHP 호스팅 지원** — Node 런타임이 필요하다. 물리적으로 불가능하다.

## 진행 방식

각 단계는 **E2E 스모크로 검증되어야 완료**입니다. 화면이 뜨는 것과 동작하는 것은
다르고, 특히 돈·개인정보·권한이 걸린 경로는 항목으로 못박아 둡니다.
현재 689개 항목이 실제 PostgreSQL과 실제 서버 프로세스로 돕니다.

# 세금 증빙

현금영수증 · 세금계산서 · 부가세 신고 자료.

> **이 영역은 틀리면 세금을 잘못 냅니다.** 부가가치세법 제32조의2·제46조에
> 따라 최종소비자가 요청하면 현금영수증을 **발급해야 하고**, 미발급은
> 미발급액의 **20% 가산세**입니다.

## 카드 결제에는 발급하지 않습니다

카드는 카드사가 국세청에 자동 통보합니다. 현금영수증을 또 발급하면 **같은
매출을 두 번 신고**하는 것이고, 손님도 이중 공제를 받게 됩니다.

그래서 Brick 은 카드 주문의 발급 요청을 **거부합니다.** 설정으로 켤 수
없습니다. 발급 대상은 **무통장 입금 · 가상계좌 · 현금** 주문입니다.

## 준비: 발급 방식 정하기

### 수동 발급 (기본값)

운영자가 **홈택스에서 직접 발급**하고, Brick 에 승인번호를 적습니다.

1. 손님이 주문 화면에서 현금영수증을 신청 → 상태 `발급대기`
2. 관리자 → 쇼핑몰 → 현금영수증 에서 목록 확인
3. 홈택스에서 발급
4. Brick 에서 **국세청 승인번호**를 입력하고 상태를 `발급완료`로 변경

> `발급대기` 는 **아직 국세청에 신고되지 않았다**는 뜻입니다. Brick 은
> 발급되지 않은 것을 "발급됨"으로 표시하지 않습니다. 승인번호 없이는
> 발급완료로 바꿀 수 없습니다 — 없으면 나중에 국세청 자료와 대조할 수
> 없습니다.

### PG 자동 발급

PG 사의 현금영수증 API 를 붙이면 자동 발급됩니다. 플러그인이
`registerCashReceiptGateway` 로 등록합니다
([플러그인 개발](plugin-development.md) 참고).

## 면세 상품 설정

도서 · 농수산물 · 의료 등은 부가세가 없습니다(부가가치세법 제26조).

상품 등록·수정 화면의 **면세 상품** 을 켜세요. 켜지 않으면 **부가세를 붙여
증빙을 발급**하고, 이는 잘못된 증빙입니다 — 손님이 부가세를 환급받을 수
없습니다.

> 데이터 이전 도구를 쓰면 기존 쇼핑몰의 면세 설정이 함께 옮겨집니다.

**과거 주문은 상품 설정을 바꿔도 달라지지 않습니다.** 주문 시점의 면세
여부가 항목에 기록되므로, 이미 신고한 증빙 금액이 흔들리지 않습니다.

## 금액은 어떻게 나뉘나

```
면세금액  = 면세 상품의 판매금액 (취소·반품 수량 제외)
과세분    = 총액 − 면세금액
공급가액  = 과세분 ÷ 1.1 (원 단위 절사)
부가세    = 과세분 − 공급가액
```

**공급가액 + 부가세 + 면세금액 = 총액**이 항상 성립합니다. 각각 반올림하면
1원이 어긋나 국세청 검증에서 반려되므로, 부가세를 차액으로 계산합니다.

증빙 금액은 **실제로 받은 돈**입니다 — 완료된 반품의 환불액을 뺍니다.

## 반품하면 증빙이 취소됩니다

**환불했는데 증빙이 살아 있으면 세금을 더 냅니다.** 반품이 `처리완료` 되면
그 주문의 현금영수증이 자동 취소됩니다.

- **교환**은 금액이 변하지 않으므로 증빙을 건드리지 않습니다
- 취소는 **전액 취소**만 합니다. 부분 반품이면 취소한 뒤 **남은 금액으로 다시
  발급**하세요 (국세청 API 가 부분 취소를 지원하지 않는 경우가 많습니다)
- 자동 취소가 실패하면 목록의 **오류** 칸에 사유가 남습니다. 그때는
  홈택스에서 직접 취소하세요

## 세금계산서

사업자 손님이 요청하면 관리자 → 쇼핑몰 → 세금계산서 요청 에 쌓입니다.

접수하는 정보: 사업자등록번호(체크섬 검증) · 상호 · 대표자 · 사업장 주소 ·
업태 · 종목 · **계산서를 받을 이메일**(필수).

처리:
- **발급완료** — 홈택스에서 발급한 뒤 국세청 승인번호를 입력합니다
- **거부** — 사유가 필수입니다. 사유 없이 거부하면 손님은 왜 못 받는지
  알 수 없습니다

> 발급하지 않으면 손님이 **매입세액을 공제받지 못합니다.** 요청이 묻히지
> 않게 목록을 정기적으로 확인하세요.

국세청 전자세금계산서 자동 연동은 사업자 인증서가 필요해서 아직 지원하지
않습니다. 이 화면의 목적은 **요청을 잃어버리지 않는 것**입니다.

## 부가세 신고 자료

관리자 → 쇼핑몰 → 리포트 → 부가세.

연도와 과세기간을 고릅니다:

| 코드 | 기간 |
|---|---|
| 제1기 예정 | 1~3월 |
| 제1기 확정 | 4~6월 |
| 제1기 전체 | 1~6월 |
| 제2기 예정 | 7~9월 |
| 제2기 확정 | 10~12월 |
| 제2기 전체 | 7~12월 |

증빙 종류로 나눠 보여줍니다 — 신고서가 그렇게 요구합니다.

| 구분 | 뜻 |
|---|---|
| 신용카드 | 카드사가 국세청에 통보 (별도 조치 불필요) |
| 현금영수증 발행분 | 발급 완료된 것 |
| 세금계산서 발급분 | 발급 완료된 것 |
| **기타** | **증빙 없는 현금 매출** |

**`기타` 를 반드시 확인하세요.** 증빙 없는 현금 매출은 발급 누락일 수 있고,
그것이 가산세의 원인입니다.

집계 기준은 [판매 리포트](reports.md)와 **같습니다** — 결제일 기준, 완료된
반품 차감. 신고 숫자와 화면 숫자가 다르면 둘 다 믿을 수 없기 때문입니다.

`CSV 내보내기` 로 엑셀에서 열 수 있습니다.

> **신고 전 세무 담당자와 확인하세요.** 이 집계는 쇼핑몰 주문만 포함하며,
> 다른 경로의 매출과 매입은 들어 있지 않습니다.

## 자주 겪는 상황

**손님이 발급을 요청했는데 오류가 납니다**
카드 결제 주문이면 발급 대상이 아닙니다. 무통장 입금 주문인지 확인하세요.

**같은 주문에 다시 발급하려면**
먼저 기존 증빙을 취소하세요. 취소된 것은 다시 발급할 수 있습니다.

**식별번호가 안 보입니다**
개인정보이므로 뒤 4자리만 표시됩니다. 발급·취소에는 저장된 원본이 쓰입니다.

**용도를 잘못 골랐다는 오류가 납니다**
소득공제용은 휴대폰 번호(10~11자리) 또는 현금영수증카드 번호(13~19자리),
지출증빙용은 사업자등록번호 10자리입니다. 사업자가 소득공제용으로 받으면
매입세액을 공제받지 못하고, 개인이 지출증빙용으로 받으면 연말정산에
잡히지 않습니다.

**부가세 자료의 합이 판매 리포트와 다릅니다**
과세기간과 리포트 기간이 다른지 확인하세요. 기준(결제일·반품 차감)은
같습니다.

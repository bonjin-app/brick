# 게시판 (brick-board)

그누보드 게시판에 대응하는 플러그인입니다. 코어를 수정하지 않고 플러그인으로만 구현되어 있습니다.

## 시작하기

관리자 → 플러그인 → **게시판** 활성화 → 사이드바의 **게시판** 메뉴에서 생성.

페이지에 노출하려면 페이지 빌더에서 블록을 배치합니다:

| 블록 | 용도 |
|---|---|
| 게시판 | 목록 + 분류 + 검색 (블록 설정에서 slug 지정) |
| 게시판 목록 | 공개 게시판 카드 목록 |
| 최근 게시물 | 사이드바·홈 위젯 |

## 기능

| 영역 | 내용 |
|---|---|
| 다중 게시판 | 게시판별 독립 설정 |
| 권한 | 읽기·쓰기·댓글·다운로드를 각각 `누구나 / 회원 / 운영자 / 관리자` 로 |
| 분류 | 게시판별 분류 목록, 목록에서 필터 |
| 답변형 | 계층 구조(최대 8단), 스레드 단위 정렬 |
| 비밀글 | 작성자·운영자만 열람 |
| 첨부파일 | 게시판별 개수 제한, 확장자 화이트리스트, 다운로드 권한·카운트 |
| 추천/비추천 | 1인 1표, 재클릭 취소 |
| 비회원 글쓰기 | 이름 + 비밀번호 (수정·삭제 확인용) |
| 댓글 | 대댓글(3단), 비밀댓글, 비회원 댓글 |
| 검색 | 제목 / 내용 / 작성자 / 전체 |
| 도배 방지 | 게시판별 작성 간격 제한 |
| 공지 | 상단 고정 (운영자만) |
| RSS | 공개 게시판만 |

## 그누보드와 다른 점

| | 그누보드 | Brick |
|---|---|---|
| 권한 | 회원 레벨 1~10 | 역할 4단계 (guest/member/manager/admin) |
| 스킨 | PHP 스킨 파일 | 블록 + 테마 (빌드 불필요) |
| 답변 정렬 | `wr_num` / `wr_reply` 문자열 | materialized path (`thread_path`) |
| 비회원 비밀번호 | 평문 저장이 흔했음 | **scrypt 해시** |
| 첨부 경로 | 원본 파일명 기반 | 서버 생성 키 (traversal·충돌 방지) |

권한을 10단계로 세분하지 않은 것은 의도적입니다. Brick의 역할 모델과 맞추고,
"레벨 5는 무엇인가"를 관리자가 매번 정의해야 하는 문제를 피합니다.
더 세밀한 권한이 필요하면 플러그인이 훅으로 확장할 수 있습니다.

## 설계에서 중요한 것

### 답변형 정렬

그누보드는 `wr_num`(음수 정렬)과 `wr_reply`(문자 코드) 조합으로 계층을 만듭니다.
Brick은 **materialized path**를 씁니다:

```
원글       thread_path = ''          depth 0
├ 답변1    thread_path = '0001'      depth 1
│ └ 답변1-1 thread_path = '0001.0001' depth 2
└ 답변2    thread_path = '0002'      depth 1
```

목록 정렬은 `ORDER BY thread_created_at DESC, thread_path ASC` 하나로 끝납니다 —
스레드가 통째로 묶이고, 새 스레드가 위로 옵니다.

동시에 같은 부모에 답변이 달릴 때 `thread_path` 가 충돌하지 않도록
스레드 원글 행을 `FOR UPDATE` 로 잠근 뒤 형제 수를 셉니다.

### 비회원 비밀번호

그누보드에서는 비회원 글 비밀번호를 평문이나 약한 해시로 두는 경우가 많았습니다.
Brick은 **scrypt 해시**로 저장합니다. argon2를 쓰지 않은 이유는 플러그인에 네이티브
의존성을 추가하면 배포본이 무거워지고 FTP 배포와 충돌하기 때문입니다 —
Node 내장 scrypt로 충분하며, 무엇보다 평문을 저장하지 않습니다.

### 첨부파일 원자성

여러 파일을 올릴 때 **전부 검증한 뒤 저장**합니다. 하나씩 검증하며 저장하면
뒤쪽 파일이 거부될 때 앞쪽 파일이 스토리지와 DB에 남습니다.
저장 중 실패하면 이미 올린 파일을 되돌립니다.

### 다운로드 권한

`GET /files/:id` 가 권한을 검사한 뒤 스토리지 URL을 발급합니다.
발급된 URL은 **추측 불가능한 키**(uuidv7 기반)지만, 한 번 발급되면 그 URL을 아는 사람은
권한 없이도 내려받을 수 있습니다(capability URL). 워드프레스도 같은 성질이며,
민감 파일을 다루려면 서명 URL을 쓰는 스토리지 구현이 필요합니다.

## API

모든 경로는 `/api/plugins/brick-board` 아래입니다.

### 공개

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/boards` | 읽을 수 있는 게시판 목록 |
| GET | `/boards/:slug/posts?page&category&q&in` | 글 목록 (`in`: all/title/content/author) |
| POST | `/boards/:slug/posts` | 글 작성 (`replyTo` 로 답변) |
| GET | `/posts/:id?pw=` | 글 읽기 (비밀글은 `pw`) |
| PUT/DELETE | `/posts/:id` | 수정·삭제 (비회원은 `guestPassword`) |
| POST | `/posts/:id/files` | 첨부 업로드 (multipart) |
| GET | `/files/:id` | 다운로드 URL 발급 |
| POST | `/posts/:id/comments` | 댓글 |
| DELETE | `/comments/:id` | 댓글 삭제 |
| POST | `/posts/:id/vote` | 추천(`value: 1`) / 비추천(`-1`) |
| GET | `/boards/:slug/rss` | RSS (공개 게시판만) |

### 관리자 (manager 이상)

`/admin/boards` (CRUD), `/admin/posts` (목록·삭제)

## 훅

| 훅 | 시점 |
|---|---|
| `board.post.created` | 글 작성 후 — `{ postId, board, authorId }` |
| `board.comment.created` | 댓글 작성 후 — `{ commentId, postId }` |

포인트 적립이나 알림을 붙이려면 이 훅을 구독하세요.

# 보안

## 구현된 방어

| 영역 | 조치 |
|---|---|
| 비밀번호 | argon2id 해시 (memory-hard, GPU 공격에 강함) |
| 세션 | 랜덤 256bit 토큰. **DB에는 sha256 해시만 저장** — DB 유출로 세션을 탈취할 수 없음 |
| 쿠키 | `httpOnly` · `sameSite=lax` · 프로덕션에서 `secure` |
| CSRF | `sameSite=lax` 로 크로스사이트 POST에 쿠키가 실리지 않음 |
| 브루트포스 | 계정별 5회/15분, IP별 50회/15분 (NAT 환경 오탐 방지) |
| 가입 스팸 | IP별 5회/시간 |
| 권한 상승 | 관리자가 자기 권한/활성 상태를 변경할 수 없음 (관리자 전멸 방지) |
| 비밀번호 변경 | 현재 비밀번호 확인 필수 + 성공 시 **모든 세션 무효화** |
| 계정 정지 | 즉시 전 세션 무효화 |
| 파일 업로드 | 확장자 **화이트리스트** + MIME 일치 검사. 저장 키는 서버 생성 |
| 경로 조작 | 정적 서빙과 ZIP 전개 모두 정규화 후 base 디렉터리 검증 (zip-slip 방어) |
| SQL 주입 | Drizzle 파라미터 바인딩. 플러그인도 `sql` 템플릿 사용 |
| XSS (콘텐츠) | 테마 템플릿 `{{ }}` 는 이스케이프, 블록 렌더는 사용자 입력 이스케이프 |
| 설정 조작 | 관리자 설정 API가 화이트리스트 방식 (`install.state` 등 변경 불가) |
| 메뉴 링크 | `javascript:` 등 위험한 스킴 차단 |
| 컨테이너 | 비-root 사용자(uid 1001)로 실행, tini로 PID 1 시그널 처리 |
| 보안 헤더 | `X-Content-Type-Options` · `X-Frame-Options` · `Referrer-Policy` |
| 설정 검증 | 프로덕션에서 약한 `BRICK_SECRET` 이면 부팅 거부 |

## 신뢰 모델 — 반드시 이해할 것

Brick은 **관리자를 신뢰합니다.** 워드프레스와 같은 모델입니다.

- `core/rich-text` 블록은 raw HTML을 그대로 출력합니다
- 테마 템플릿은 `{{{ }}}` 로 raw HTML을 삽입할 수 있습니다
- 플러그인은 서버 프로세스 안에서 **제약 없이** 실행됩니다 — 파일 시스템과 DB에 접근할 수 있습니다

따라서:

> **관리자 권한은 서버 권한과 사실상 동등합니다.**
> 신뢰하지 않는 사람에게 관리자 권한을 주지 마세요.
> 출처가 불분명한 플러그인을 설치하지 마세요.

일반 회원(`member`)은 이런 권한이 없습니다 — 글쓰기와 댓글만 가능합니다.

## 배포 시 체크리스트

- [ ] `BRICK_SECRET` 을 `openssl rand -base64 32` 로 생성해 설정
- [ ] `NODE_ENV=production` 설정
- [ ] `POSTGRES_PASSWORD` 를 기본값(`brick`)에서 변경
- [ ] HTTPS 적용 (Let's Encrypt / Cloudflare)
- [ ] 프록시 뒤라면 `BRICK_TRUST_PROXY=true` — **설정하지 않으면 요청 제한이 무력화됩니다**
- [ ] 내부 API 포트(3001)를 외부에 노출하지 않음 (Docker는 기본적으로 노출하지 않음)
- [ ] PostgreSQL 포트를 외부에 노출하지 않음
- [ ] 관리자 계정에 강한 비밀번호
- [ ] 자동 백업 설정 ([운영 가이드](operations.md#백업))
- [ ] 불필요하면 회원가입 닫기 (관리자 → 설정)

## 알려진 제약

- **2FA 미지원** — 로드맵에 있습니다. 그전까지는 강한 비밀번호와 접근 IP 제한으로 보완하세요.
- **감사 로그 없음** — 누가 무엇을 바꿨는지 추적되지 않습니다.
- **요청 제한이 인메모리** — 다중 인스턴스에서는 인스턴스별로 따로 계산됩니다.
- **이메일 인증 없음** — `email_verified_at` 컬럼은 있으나 발송 기능이 미구현입니다.
- **비밀번호 재설정 없음** — 관리자가 DB에서 직접 처리해야 합니다.

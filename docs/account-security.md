# 계정 보안

2단계 인증 · 접속 기기 관리 · 감사 로그.

> **관리자 계정이 뚫리면 사이트 전체를 잃습니다.** 회원 개인정보, 주문 내역,
> 결제 정보 접근 권한이 한 계정에 몰려 있습니다. 재사용한 비밀번호는 다른
> 사이트 유출로 뚫리고, 그 사실을 알 방법이 없습니다.

## 2단계 인증 (2FA)

인증 앱이 30초마다 만드는 6자리 코드를 로그인에 함께 씁니다. 비밀번호가
유출되어도 휴대폰이 없으면 들어올 수 없습니다.

지원하는 앱: Google Authenticator · Authy · 1Password · Microsoft
Authenticator 등 **TOTP 표준을 쓰는 모든 앱**.

### 켜기

마이페이지 → 계정 보안.

1. **비밀번호를 입력**합니다 (세션만으로는 켤 수 없습니다 — 누가 내 컴퓨터를
   쓰고 있을 때 자기 앱을 등록해 계정을 빼앗는 것을 막습니다)
2. QR 코드를 인증 앱으로 찍습니다
3. 앱에 표시된 **6자리 코드를 입력**합니다
4. **복구 코드 10개**를 저장합니다

> **3번을 통과하기 전에는 켜지지 않습니다.** 잘못 등록된 상태로 켜지면
> 본인이 영구히 잠기기 때문입니다.

> **복구 코드는 이때 한 번만 표시됩니다.** 인쇄하거나 비밀번호 관리자에
> 저장하세요. 휴대폰을 잃으면 이 코드로만 들어올 수 있습니다.

### 로그인

1. 이메일과 비밀번호 입력
2. 인증 앱의 6자리 코드 입력

코드 대신 **복구 코드**를 입력해도 됩니다. 하이픈과 대소문자는 무시하므로
`a1b2c-3d4e5` 든 `A1B2C3D4E5` 든 됩니다.

복구 코드는 **한 번 쓰면 소진**됩니다. 쓸 때마다 남은 개수를 알려주니,
적어지면 재발급하세요 (마이페이지 → 계정 보안 → 복구 코드 재발급).
재발급하면 **이전 코드는 모두 무효**가 됩니다.

### 자주 겪는 상황

**"코드가 맞지 않습니다"**
휴대폰 시계가 틀어져 있을 수 있습니다. 앞뒤 30초까지만 받아들입니다.
휴대폰 설정에서 시간 자동 설정을 켜세요.

**"이미 사용한 코드입니다"**
같은 코드를 두 번 쓸 수 없습니다(가로챈 코드의 재사용을 막습니다).
30초를 기다려 다음 코드를 쓰세요.

**"시도 횟수를 초과했습니다"**
한 번의 로그인 시도에서 코드는 5번까지 입력할 수 있습니다. 넘으면 비밀번호부터
다시 입력해야 합니다.

**휴대폰을 잃었고 복구 코드도 없습니다**
데이터베이스에 직접 접근할 수 있으면 해당 행을 지워 해제할 수 있습니다:

```bash
psql "$DATABASE_URL" -c "DELETE FROM user_totp WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com')"
```

이 방법밖에 없습니다. **복구 코드를 반드시 저장해두세요.**

## 관리자에게 2FA 강제하기

관리자 → 설정 → `관리자·운영자 2단계 인증 필수`.

켜면:
- 2FA 를 켜지 않은 관리자는 **관리 작업을 할 수 없습니다**
- 관리자·운영자는 **스스로 해제할 수 없습니다** (끌 수 있으면 강제가 아닙니다)

**로그인 자체는 막지 않습니다.** 설정을 켠 순간 아무도 못 들어오면 등록할
방법이 없어 사이트가 영구히 잠깁니다. 로그인해서 계정 보안 화면에서 등록하면
관리 작업이 열립니다.

일반 회원에게는 적용되지 않습니다 (원하면 스스로 켤 수 있습니다).

## 접속 기기 관리

마이페이지 → 계정 보안 → 접속 중인 기기.

지금 내 계정으로 로그인된 모든 기기를 봅니다. **모르는 기기가 보이면 계정이
뚫린 것입니다.**

| 항목 | 뜻 |
|---|---|
| 기기 | `Mac · Chrome` 처럼 사람이 읽는 형태 |
| 현재 기기 | 지금 보고 있는 이 브라우저 |
| 마지막 사용 | 최근 접속 시각 |

할 수 있는 것:
- **하나 끊기** — 그 기기의 로그인이 즉시 풀립니다
- **다른 기기 모두 끊기** — 지금 기기만 남깁니다. 계정이 뚫렸다고 의심할 때
  누르세요 (자기까지 끊으면 다시 로그인하는 사이에 공격자가 먼저 들어올 수
  있어서, 지금 기기는 남깁니다)

기기를 모두 끊은 뒤에는 **비밀번호를 바꾸고 2FA 를 켜세요.**

> 접속 IP 는 **해시로만** 저장합니다. 접속 위치 이력은 보관할 이유가 없는
> 개인정보이기 때문입니다.

## 감사 로그

관리자 → 감사 로그.

관리 작업이 기록됩니다 — 누가, 언제, 무엇을 했는지. **보관 기간은 180일**이고
그보다 오래된 기록은 정리 작업이 지웁니다.

좁히는 방법:

| 필터 | 설명 |
|---|---|
| 동작 | `auth.totp_enabled`, `shop.order_status_changed` 등 |
| 행위자 | 이메일 **부분 일치**. 정확한 주소를 몰라도 찾습니다 |
| 기간 | 시작일 ~ 종료일. **종료일 그날 끝까지** 포함합니다 |

날짜는 **사이트 시간대**(기본 한국 시간) 기준입니다. UTC 로 자르면 오전
9시 이전 기록이 전날로 밀려 엉뚱한 범위를 보게 됩니다.

기록되는 보안 관련 동작:

| 동작 | 뜻 |
|---|---|
| `auth.totp_challenge_issued` | 비밀번호는 맞고 코드 대기 |
| `auth.login_2fa` | 2FA 코드로 로그인 |
| `auth.login_recovery_code` | **복구 코드로 로그인** (주의해서 볼 것) |
| `auth.totp_enabled` / `auth.totp_disabled` | 2FA 켜기 / 끄기 |
| `auth.recovery_codes_regenerated` | 복구 코드 재발급 |
| `auth.session_revoked` | 기기 하나 끊기 |
| `auth.other_sessions_revoked` | 다른 기기 모두 끊기 |

> `auth.login_recovery_code` 가 예상 없이 보이면 확인하세요 — 정상적인
> 사용자는 휴대폰을 잃었을 때만 씁니다.

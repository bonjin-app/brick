# 페이지 배치 편집기

관리자 → **페이지**에서 페이지를 열면 세 칸이 나옵니다.

| 칸 | 하는 일 |
|---|---|
| 왼쪽 **구성** | 블록 트리. 끌어서 순서를 바꾸고, **다단 레이아웃 안에 넣습니다** |
| 가운데 **미리보기** | 저장하지 않은 지금 내용을 **사이트의 실제 테마로** 그립니다. 누르면 그 블록을 고릅니다 |
| 오른쪽 **블록 · 페이지 설정** | 고른 블록의 설정, 그리고 제목·주소·공개 상태·SEO·이전 버전 |

전에는 블록을 폼 카드로 세로로 늘어놓았습니다 — 어떻게 놓이는지는 저장하고 사이트를 열어야
알았고, 다단 레이아웃은 안에 블록을 넣을 길이 없어 빈 틀뿐이었습니다.

## 쓰는 법

- **블록 추가** — 구성 아래의 "+ 블록 추가" 는 맨 끝에, 블록을 고른 뒤 오른쪽의 "이 블록 뒤에 추가"·
  "이 안에 블록 추가"(다단 레이아웃 같은 컨테이너)는 그 자리에 넣습니다. 블록 서랍은 이름으로 찾을 수 있습니다.
- **옮기기** — 구성에서 끌어다 놓습니다. 줄의 위·아래쪽에 놓으면 그 앞·뒤로, 컨테이너 줄의 가운데에 놓으면
  그 안으로 들어갑니다. 자기 자신이나 자기 안쪽으로는 옮겨지지 않습니다.
- **키보드로** — 구성의 블록 이름에 Tab 으로 가서 Enter 로 고른 뒤, 오른쪽 단추로 위로·아래로·밖으로 빼기·
  위 다단 레이아웃 안으로 넣기·복제·삭제를 합니다. 끌어다 놓기로 할 수 있는 배치는 모두 키보드로도 됩니다.
- **되돌리기** — Ctrl+Z / Ctrl+Shift+Z(맥은 ⌘). 입력 칸 안에서는 그 칸의 글자 되돌리기가 먼저입니다. 같은 칸을
  이어서 고친 것은 한 번으로 묶입니다.
- **화면 폭** — 데스크톱·태블릿(768px)·모바일(390px). 테마의 반응형 규칙이 그대로 적용된 모습입니다.
- 미리보기는 **손님이 보는 모습**(로그인하지 않은 화면)입니다. 링크·폼은 미리보기 안에서 눌러도 이동하지
  않습니다 — 누르면 그 블록을 고를 뿐입니다.
- 빈 다단 레이아웃과 **모르는 블록**(확장을 끈 뒤 남은 블록)도 미리보기에 표시되어 눌러서 고르고 지울 수 있습니다.
  공개 화면에서는 보이지 않습니다.
- 편집은 **저장을 눌러야** 사이트에 반영됩니다. 저장할 때마다 이전 버전이 한 판씩 쌓입니다.

## 어떻게 동작하나

1. 편집할 때마다(0.35초 쉬면) 편집기가 초안을 서버에 맡깁니다 — `POST /api/admin/pages/draft-preview`.
   초안은 **맡긴 운영자 한 사람의 칸**(편집기 창마다 하나)에 10분 동안 있고, 저장되지 않습니다.
2. 미리보기 창이 `GET /api/admin/pages/draft-preview/<창 이름>` 을 엽니다. 서버가 초안을 공개 화면과 같은
   렌더러·테마로 그리되, 블록마다 트리 위치(`data-brick-node="1.0"`)를 단 상자로 감싸고 편집기와 이야기하는 작은
   스크립트를 붙입니다.
3. 미리보기에서 누르면 그 위치가 편집기로 가고(같은 출처끼리만), 편집기가 고른 블록을 미리보기에 테두리로 보여 줍니다.

왜 편집기가 HTML 을 받아 직접 넣지 않나: 미리보기 창이 **사이트와 같은 주소·같은 보안 정책(CSP)** 으로 떠야
테마의 글꼴·스크립트가 공개 화면과 똑같이 돕니다. 관리 화면 안에 HTML 을 넣으면 관리 화면의 정책을 물려받아
미리보기가 공개 화면과 달라집니다.

지키는 것:

- 초안은 **다른 운영자도 보지 못합니다**(창 이름을 알아도 운영자마다 칸이 다르다). 회원·손님은 맡기지도 보지도 못합니다.
- 미리보기 응답은 캐시되지 않고(`no-store`) 검색엔진에 올라가지 않습니다(`noindex`). 렌더 캐시를 거치지 않으므로
  저장하지 않은 내용이 손님에게 나갈 길이 없습니다.
- 공개 렌더에는 위치 표시도 편집기 스크립트도 없습니다 — 스모크가 로그인한 운영자의 공개 화면까지 확인합니다.
- **모양이 틀린 블록 트리는 저장하지 않습니다**(블록 이름이 없거나, 속성이 객체가 아니거나, 안쪽 블록 목록이
  배열이 아닌 것). 한 페이지에 블록 2,000개, 12단까지입니다.

## 플러그인 개발자

컨테이너 블록은 `acceptsChildren: true` 를 선언하고 `ctx.children`(안쪽 블록들의 HTML)을 그립니다.
편집기는 이 선언을 보고 "이 안에 블록 추가" 와 끌어다 넣기를 엽니다.

```ts
ctx.registerBlock({
  name: "tabs",                // "my-plugin/tabs" 로 네임스페이스된다
  displayName: "탭",
  acceptsChildren: true,
  render: async (props, blockCtx) => `<div class="tabs">${(blockCtx.children ?? []).join("")}</div>`,
});
```

- 미리보기에서는 안쪽 블록 하나하나가 위치 표시 상자로 감싸여 `ctx.children` 에 들어옵니다. 자식 HTML 을 문자열로
  쪼개거나 고쳐 쓰지 마세요 — 그대로 이어 붙이면 공개 화면과 미리보기가 같게 그려집니다.
- 안쪽 블록이 하나도 없으면 미리보기에서만 "빈 칸" 자리가 자식으로 들어옵니다(눌러서 고를 수 있게).

## 아직 없는 것

- 미리보기 **안에서** 끌어다 놓기 — 지금은 구성(왼쪽)에서 옮깁니다.
- 글자를 미리보기 안에서 바로 고치기(인라인 편집) — 오른쪽 설정 칸에서 고칩니다.
- 칸 너비 비율 같은 컨테이너의 세부 배치 — 다단 레이아웃은 안쪽 블록 수만큼 같은 폭으로 나뉩니다.

# 그누보드5 · 영카트5에서 옮겨오기

10년 쌓인 게시글·회원과 쇼핑몰 상품·주문을 그대로 가져옵니다. **회원은 그누보드에서 쓰던
비밀번호로 그대로 로그인합니다** — 전원이 비밀번호를 다시 만들어야 하면
상당수가 돌아오지 않기 때문입니다.

---

## 먼저 알아야 할 것

**덤프 파일로 옮깁니다.** 원격 MySQL 접속을 요구하지 않습니다 — 공유 호스팅은
외부 접속을 막는 경우가 대부분이고, 여러분이 실제로 손에 넣을 수 있는 것은
phpMyAdmin 내보내기 파일입니다.

**반드시 리허설을 먼저 보세요.** 이전은 되돌리기 어렵습니다. 리허설은 아무것도
쓰지 않고 무엇이 몇 건 옮겨지는지, 무엇이 **안** 옮겨지는지, 레벨이 어떤 역할로
접히는지 보여줍니다.

**설치가 끝난 Brick 에 넣는 작업입니다.** 먼저 Brick 을 설치하고 게시판·포인트·
쇼핑몰 플러그인을 활성화한 뒤 이전하세요 — 플러그인이 없으면 그 데이터는
건너뛰고 리허설이 알려줍니다.

## 1. 덤프 만들기

### phpMyAdmin

1. 그누보드 데이터베이스를 선택합니다.
2. **내보내기** → 방식 **빠르게** → 형식 **SQL** → 실행.
3. `.sql` 파일이 내려옵니다.

큰 사이트라면 **사용자 지정** 방식에서 `g5_visit` · `g5_login` · `g5_popular` 를
제외하세요. 어차피 옮기지 않는 데이터이고 파일 크기의 대부분을 차지합니다.

### 서버에서 직접

```bash
mysqldump -u <사용자> -p <데이터베이스> \
  --default-character-set=utf8mb4 \
  --ignore-table=<데이터베이스>.g5_visit \
  --ignore-table=<데이터베이스>.g5_login \
  > gnuboard.sql
```

## 3. 레벨 매핑 조정

그누보드의 회원 레벨 1~10을 Brick의 4단 역할로 접습니다. 레벨 숫자의 의미는
사이트마다 다르므로 **조용히 결정하지 않고** 조정받습니다 (ADR-25).

| 기본값 | 의미 |
|---|---|
| `adminFrom: 10` | 레벨 10 이상 → `admin` |
| `managerFrom: 8` | 레벨 8~9 → `manager` |
| 그 아래 | → `member` |

```bash
node scripts/migrate-gnuboard.mjs --dump gnuboard.sql --admin-from 9 --manager-from 6
```

게시판 권한은 경계가 다릅니다. 그누보드에서 **읽기 레벨 1은 "비회원도 읽기"**를
뜻하므로 `guest` 로, 2 이상이면 로그인이 필요하므로 `member` 이상으로 접힙니다.

```bash

```

게시판을 골라 옮기거나 일부를 건너뛸 수 있습니다.

```bash
... --run --boards notice,free,qna    # 이 게시판만
... --run --no-points                 # 포인트 제외
... --run --no-members                # 회원 제외 (이미 옮긴 경우)
```

**다시 실행해도 안전합니다.** 이미 있는 회원·게시판·포인트는 건너뜁니다.
중간에 실패했다면 그대로 다시 실행하세요.

## 비밀번호는 어떻게 보존되는가

그누보드가 쓰는 해시를 **그대로 저장**하고, 회원이 처음 로그인할 때 그 해시로
검증합니다. 검증에 성공하면 그 순간 argon2id 로 다시 해시합니다(자동 승급).
회원은 아무것도 하지 않습니다.

| 그누보드 | 지원 |
|---|---|
| 5.3+ `password_hash()` = bcrypt `$2y$` | ✅ |
| 구형 MD5 (32자 hex) | ✅ |
| sha256 (64자 hex) | ✅ |
| 그 외 | ❌ 비밀번호 로그인이 막히고, 재설정 안내가 필요합니다 |

**왜 승급하는가.** 그누보드의 MD5 는 지금 기준으로 안전하지 않습니다 — 유출되면
사실상 평문입니다. 그대로 두면 이전한 사이트는 영구히 약한 해시를 갖습니다.
로그인 시점은 평문 비밀번호가 손에 있는 **유일한 승급 기회**입니다.

형식을 알 수 없는 해시는 임의로 추측하지 않습니다. 추측해서 검증하면 잘못된
비밀번호를 통과시킬 위험이 있습니다. 그 회원들에게는 비밀번호 재설정 메일을
안내하세요.

## 첨부파일과 본문 이미지

파일 자체는 DB 에 없으므로 별도로 복사해야 합니다. **본문·상품의 이미지
주소는 이전할 때 자동으로 바꿔 둡니다** — 복사만 하면 뜹니다.

| 그누보드 | Brick 으로 복사 | 본문 주소 (자동 변환) |
|---|---|---|
| `data/file/` | `uploads/` | `/data/file/…` → `/uploads/…` |
| `data/editor/` | `uploads/editor/` | `/data/editor/…` → `/uploads/editor/…` |
| `data/item/` (영카트) | `uploads/item/` | `/data/item/…` → `/uploads/item/…` |

```bash
# 그누보드 서버에서
tar czf data.tar.gz data/file/ data/editor/ data/item/

# Brick 서버에서
tar xzf data.tar.gz
cp -r data/file/*   /path/to/brick/uploads/
cp -r data/editor/* /path/to/brick/uploads/editor/
cp -r data/item/*   /path/to/brick/uploads/item/
```

본문에 옛 사이트의 **절대주소**(`https://old-site.com/data/...`)가 들어
있다면 실행할 때 `oldBaseUrl` 을 함께 넘기세요 — 그 주소도 잡습니다.
남의 서버를 가리키는 이미지(외부 CDN 등)는 건드리지 않습니다.

변환 없이 리버스 프록시로 옛 경로를 그대로 서빙하려면 `imageRewrite: false`
로 끄고 아래처럼 돌립니다:

```nginx
location /data/file/ {
  alias /path/to/brick/uploads/;
}
```

## 영카트 (쇼핑몰)

영카트는 그누보드5 위에 얹힌 쇼핑몰이고 **테이블 접두어를 공유**합니다
(`g5_shop_item`, `g5_shop_order`, ...). 그래서 덤프 하나로 회원·게시판과
상품·주문을 함께 옮깁니다. 제외하려면 `--no-shop` 을 붙이세요.

### 분류 계층을 복원합니다

영카트의 `ca_id` 는 계층을 문자열 길이로 표현합니다.

```
"10"     → 대분류        (의류)
"1010"   → 그 아래 중분류 (상의)
"101010" → 소분류
```

부모는 **앞자리를 자른 값**입니다. 이걸 알아야 계층이 복원됩니다 —
짧은 것부터 처리해 부모가 항상 먼저 만들어지게 합니다.

### 상품 상태

| 영카트 | Brick | 왜 |
|---|---|---|
| `it_use = 0` | `hidden` | `draft` 가 아닙니다 — draft는 "아직 안 만든 것", 이건 "팔다가 내린 것" |
| `it_soldout = 1` | `soldout` | |
| 그 외 | `selling` | **재고 0을 품절로 자동 전환하지 않습니다** — 영카트에서 재고를 관리하지 않는 상품이 흔합니다 |

정가(`it_cust_price`)가 판매가보다 낮으면 버립니다. 그대로 두면 할인 표시가
거꾸로 됩니다.

### 상품 주소(slug)

`it_id` 는 `20240115123456` 같은 타임스탬프라 주소에 그대로 쓸 수 없습니다.
상품명에서 만들되 **id를 접미사로 붙여** 유일성을 보장합니다.

한글 상품명은 slug 규칙(영문 소문자·숫자·하이픈)에 맞는 문자가 하나도 없는
경우가 많아, 상품명만으로 만들면 전부 같은 slug가 되어 충돌합니다.

### 조합형 옵션

색상+사이즈 같은 조합형 옵션은 Brick의 단층 모델로 표현할 수 없어
**조합을 하나의 이름으로 펼칩니다** (`흰색,M`). 영카트도 화면에서는 조합을
한 줄로 보여주므로 고객이 보는 것은 같습니다.

`io_use = 0` 인 옵션은 제외합니다.

### 주문 상태

영카트는 한글 문자열을 그대로 저장합니다(`od_status = '주문'`, `'입금'`, ...).

| 영카트 | Brick |
|---|---|
| 주문 | 입금대기 |
| 입금 | 결제완료 |
| 준비 | 상품준비중 |
| 배송 | 배송중 |
| 완료 | 배송완료 |
| 취소 | 취소 |
| 반품 · 품절 | 환불 |
| **그 외** | **입금대기** |

알 수 없는 값을 임의로 '완료'로 보면 배송하지 않은 주문이 완료 처리되고
매출 통계가 부풀려집니다. 리허설이 그런 값을 목록으로 알려줍니다.

### 주문번호를 그대로 씁니다

고객이 알고 있는 번호이고, 문의가 오면 그 번호로 찾아야 합니다.

### 금액이 맞지 않으면 총액을 신뢰합니다

`od_cart_price + od_send_cost ≠ od_receipt_price` 인 주문이 실제로 있습니다
(쿠폰·마일리지·수동 조정). 차액을 **할인**으로 흡수해
`상품금액 - 할인 + 배송비 = 총액` 을 지킵니다 — 실제로 받은 돈이 총액입니다.

### 우편번호

구버전(`od_zip1` 3자리 + `od_zip2` 3자리)과 신버전(`od_zip` 5자리)을 모두 받습니다.
오래된 사이트가 옮겨오는 것이 이 도구의 목적입니다.

### 과거 주문을 옮겨도 재고가 줄지 않습니다

이미 팔린 것은 영카트 재고에 반영되어 있고, 우리는 그 **최종 재고 값**을 그대로
가져옵니다. 여기서 또 차감하면 재고가 음수가 됩니다.

판매수량은 주문 항목에서 다시 셉니다(취소·반품 제외).

### 상품 이미지

영카트는 `it_img1 ~ it_img10` 에 **파일명만** 저장하고 파일은
`data/item/` 에 있습니다. 이전할 때 주소를 `/uploads/item/<파일명>` 으로
만들어 두므로, 파일만 복사하면 뜹니다.

```bash
# 영카트 서버에서
tar czf item.tar.gz data/item/

# Brick 서버에서
tar xzf item.tar.gz
cp -r data/item/* /path/to/brick/uploads/item/
```

### 옮긴 뒤 확인할 것 (쇼핑몰)

- [ ] 분류 계층이 맞는가 (대·중·소분류)
- [ ] 판매 중지했던 상품이 다시 노출되지 않는가
- [ ] 옵션 재고가 맞는가
- [ ] 주문 상태가 맞는가 — 특히 '알 수 없는 상태'로 분류된 것들
- [ ] 매출 통계가 영카트와 비슷한가
- [ ] 재고가 음수가 아닌가
- [ ] 상품 이미지가 뜨는가

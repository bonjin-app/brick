# 1:1 문의 · FAQ · 설문조사 · 검색엔진 노출

그누보드의 Q&A · FAQ · 설문조사에 대응하는 기능과, 검색엔진이 사이트를 제대로 읽게 하는 설정입니다.

---

## 1:1 문의

`brick-helpdesk` 플러그인입니다. 관리자 → 플러그인에서 활성화하고,
페이지에 **1:1 문의** 블록을 배치하면 동작합니다.

### 왜 게시판으로 만들지 않았나

게시판은 **기본이 공개**이고 비밀글이 예외입니다. 문의는 반대여야 합니다.
게시판에 비밀글 옵션을 켜서 쓰면 체크박스를 놓치는 순간 주문번호·연락처·환불
계좌가 공개됩니다. 그래서 helpdesk에는 **"공개 문의" 옵션 자체가 없습니다.**
공개 질문답변이 필요하면 게시판을 쓰세요.

### 남의 문의는 "없다"고 답합니다

권한이 없으면 403이 아니라 **404**입니다. 403을 주면 "그 문의가 존재한다"는
사실이 새어 나가고, 문의번호는 순차적(`Q202608-00001`)이라 훑으면 접수 건수와
활동 시기를 알 수 있습니다.

### 답변 상태는 양방향입니다

| 상태 | 언제 |
|---|---|
| `open` 접수 | 새 문의, 또는 **작성자가 다시 글을 쓴 뒤** |
| `answered` 답변완료 | 운영자가 답변한 뒤 |
| `closed` 종료 | 운영자가 종료. 더 이상 답변을 받지 않음 |

한 방향만 있으면 "답변했는데 또 물어본" 문의가 목록에서 사라져 운영자가 놓칩니다.
관리 목록은 `open` 을 항상 위에 올립니다.

### 대화가 이어집니다

답변을 티켓에 한 칸으로 두지 않았습니다. 실제 문의는 한 번에 끝나지 않고
"추가로 여쭤봅니다 → 답변 → 확인했습니다"로 이어집니다.

### 비회원 문의

기본은 꺼져 있습니다. 켜면(**관리자 → 문의 설정 → 비회원 허용**) 이름 · 이메일 ·
조회용 비밀번호를 받습니다.

- **이메일은 필수입니다.** 비회원은 답변을 확인할 방법이 메일뿐입니다.
- 조회 비밀번호는 scrypt 해시로 저장합니다(게시판 비회원 글과 같은 방식).
- 조회는 `?pw=...` 로 합니다. 링크로 공유할 수 있어야 하기 때문인데,
  **비밀번호가 주소에 남으므로 접근 로그에 쿼리스트링을 기록하지 마세요**
  (리버스 프록시 설정 — [운영 가이드](operations.md) 참고).

### 도배 방지

문의는 메일 알림을 유발하므로 스팸의 표적입니다. 1분에 1건으로 제한합니다
(회원은 계정별, 비회원은 IP별).

### 탈퇴하면 문의는 삭제됩니다

게시글은 익명화해서 남기지만 문의는 **지웁니다.** 내용에 주문번호·연락처·환불
계좌가 들어 있고, 익명화만 하면 그 개인정보가 그대로 남습니다.
보존 의무가 있는 것은 주문 기록이고, 그건 쇼핑몰 쪽에 남습니다.

남의 문의에 남긴 운영자 답변은 익명화만 합니다 — 답변 내용은 다른 사용자에게
전달된 정보이고, 지우면 그 사람의 문의가 반쪽이 됩니다.

## FAQ

### `<details>` 로 만들었습니다

자체 아코디언을 구현하지 않았습니다. `<details>`/`<summary>` 는 JS 없이 접히고,
검색엔진은 접힌 답변까지 다 읽습니다. 직접 만들면 JS가 실패한 환경에서 답변이
아예 보이지 않습니다.

### 조회수와 "도움이 되었나"

답변 품질을 측정하는 유일한 신호입니다. **많이 읽히고 도움이 안 된 항목**이
고쳐야 할 대상입니다.

평가에 로그인을 요구하지 않습니다 — 요구하면 아무도 누르지 않고, 그러면 신호가
아예 없습니다. 같은 IP의 중복은 24시간 무시합니다. 조작될 수 있지만 절대값이
아니라 항목 간 비교에 쓰므로 견딥니다.

### 답변에는 HTML을 쓸 수 있습니다

FAQ 답변은 관리자만 작성하므로 HTML을 그대로 렌더합니다. **질문은 이스케이프**
합니다 — 목록·검색 결과에 그대로 나가는 값이라 새니타이즈 대상입니다.

## sitemap.xml · robots.txt

코어 기능입니다. 별도 설정 없이 동작합니다.

```
https://<사이트>/sitemap.xml        인덱스
https://<사이트>/sitemap-1.xml      조각 (2,000 URL)
https://<사이트>/robots.txt
```

### 왜 조각으로 나누는가

그누보드 사이트는 게시글이 십만 건인 경우가 흔합니다. 한 파일에 다 담으면
메모리가 터지고 응답도 느려집니다. 인덱스가 조각 목록을 주고, 각 조각이
요청될 때 그 구간만 읽습니다.

### 무엇이 들어가고 무엇이 빠지는가

**들어갑니다** — 홈, 발행된 페이지, 공개 게시판의 공개 게시글, 판매중·품절 상품,
FAQ 분류.

**빠집니다** — 비밀글, 비공개 게시판(`read_role` 이 `guest` 가 아닌 것),
임시·숨김 상품, 1:1 문의, 관리자 화면.

검색엔진에 노출되면 안 되는 것이 사이트맵에 들어가면 **그 자체가 유출**입니다.
스모크 테스트가 이것을 항목으로 확인합니다.

### 검색 노출을 끄려면

개발 중인 사이트가 색인되는 것은 되돌리기 어렵습니다. `site.seo_noindex` 설정을
켜면 `robots.txt` 가 전체를 막습니다.

```
User-agent: *
Disallow: /
```

### 플러그인을 만든다면

공개 URL을 만드는 플러그인은 사이트맵에 등록해야 합니다. 등록하지 않으면
검색엔진이 그 주소를 찾지 못합니다.

```ts
ctx.registerSitemapSource({
  label: "내 콘텐츠",
  count: async () => {
    const { rows } = await db.execute(sql`SELECT count(*) AS n FROM my_table WHERE is_public`);
    return Number(rows[0]?.n ?? 0);
  },
  page: async ({ offset, limit }) => {
    const { rows } = await db.execute(sql`
      SELECT slug, updated_at FROM my_table WHERE is_public
      ORDER BY created_at, id           -- 정렬은 안정적이어야 한다
      LIMIT ${limit} OFFSET ${offset}
    `);
    return rows.map((r) => ({ path: `/my/${r.slug}`, lastmod: r.updated_at }));
  },
});
```

**정렬을 안정적으로 하세요.** 페이지를 나눠 읽는 동안 순서가 바뀌면 어떤 URL은
두 번 나오고 어떤 URL은 빠집니다. `created_at` 처럼 변하지 않는 컬럼으로
정렬하고 동률은 `id` 로 깨세요.

**비공개 콘텐츠를 빼세요.** 권한이 필요한 주소를 넣으면 검색 결과에 노출되고,
누가 눌러도 403이 뜨는 링크가 색인됩니다.

## 설문조사

`brick-poll` 플러그인입니다. 관리자 → 플러그인에서 활성화하고, 페이지에
**설문조사** 블록을 배치합니다.

### 중복 투표 방지

| 투표 자격 | 식별 |
|---|---|
`누구나` | IP를 **해시로만** 저장 (원문은 남기지 않습니다) |
`회원만` | 로그인 계정 |

**IP 방식은 완벽하지 않습니다.** 같은 공유기 아래 여러 사람이 한 표로 묶입니다.
완벽한 방지는 본인 인증뿐이고 설문에 그 비용을 요구할 수는 없으니, 정확한 표가
필요하면 **회원만**으로 두세요.

해시에 설문 id를 섞습니다 — 같은 IP가 여러 설문에서 같은 해시를 갖지 않아,
해시를 모아도 "이 사람이 참여한 설문 목록"을 만들 수 없습니다.

### 결과 공개 시점

| | 언제 보이는가 |
|---|---|
`항상 공개` | 참여율을 보여주고 싶을 때 |
`투표 후 공개` | **기본값.** 표가 한쪽으로 쏠리는 것(밴드왜건)을 줄입니다 |
`종료 후 공개` | 쏠림을 완전히 막습니다 |

숨겨야 할 때는 **득표 수를 응답에 넣지 않습니다.** 화면에서 가리는 방식이면
개발자 도구로 볼 수 있습니다.

### 선택지를 고쳐도 표는 유지됩니다

이름으로 짝지어 갱신합니다. 진행 중인 설문의 오타를 고쳤을 뿐인데 표가 0이 되면
안 되기 때문입니다. **목록에서 뺀 선택지의 표는 사라지지만**, 참여자 수는
그대로입니다 — 그 사람들은 실제로 참여했습니다.

### 기타 의견

작성자 없이 내용만 봅니다. 설문은 익명이 전제이고, "누가 무슨 의견을 냈는가"를
운영자가 볼 수 있으면 그 전제가 깨집니다.

### 탈퇴하면

**표는 남고 사람만 지워집니다.** 투표를 지우면 집계가 바뀌어 이미 발표된 결과가
소급해서 달라집니다. 기타 의견은 자유 서술이라 개인을 특정할 수 있어 삭제합니다.

## 최신글 모아보기

여러 게시판의 최신글을 나란히 보여주는 블록입니다. 그누보드 메인 화면의
`latest()` 를 게시판마다 호출하는 그 구조입니다.

페이지 빌더에서 **최신글 모아보기 (여러 게시판)** 블록을 배치하고,
게시판 slug를 쉼표로 적습니다 (`notice,free,qna`). **적은 순서대로** 배치됩니다.
비우면 공개 게시판 전체가 순서대로 나옵니다.

게시판 수만큼 쿼리하지 않습니다 — 윈도우 함수로 한 번에 가져옵니다.
메인 페이지는 가장 많이 열리는 화면이고, 게시판이 열 개면 쿼리가 열 번이 됩니다.

## API

### 1:1 문의

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/plugins/brick-helpdesk/config` | 분류 목록, 비회원 허용 여부 |
| POST | `.../tickets` | 문의 접수 |
| GET | `.../my/tickets` | 내 문의 목록 |
| GET | `.../tickets/:id?pw=` | 문의 상세 + 대화 |
| GET | `.../tickets/by-no/:ticketNo?pw=` | 문의번호로 조회 |
| POST | `.../tickets/:id/replies` | 답변 · 추가 문의 |
| GET | `.../admin/tickets` | 전체 목록 (운영자) |
| PUT | `.../admin/tickets/:id` | 답변 · 상태 · 담당자 (운영자) |
| PUT | `.../admin/settings` | 문의 설정 (운영자) |

### FAQ

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `.../faqs?category=&q=` | 목록 · 검색 |
| GET | `.../faq-categories` | 분류 목록 |
| POST | `.../faqs/:id/viewed` | 조회수 |
| POST | `.../faqs/:id/rate` | 도움이 되었나 |
| GET/POST/PUT/DELETE | `.../admin/faqs` | FAQ 관리 (운영자) |
| GET/POST/PUT/DELETE | `.../admin/faq-categories` | 분류 관리 (운영자) |

### 설문조사

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/plugins/brick-poll/polls` | 진행 중인 설문 목록 |
| GET | `.../polls/:idOrSlug` | 설문 조회 (결과는 공개 시점에 따라) |
| POST | `.../polls/:idOrSlug/vote` | 투표 (응답에 투표 후 상태 포함) |
| GET/POST/PUT/DELETE | `.../admin/polls` | 설문 관리 (운영자) |
| GET | `.../admin/polls/:id/comments` | 기타 의견 (작성자 없이) |

### 훅

| 훅 | 시점 |
|---|---|
| `poll.voted` | 투표 완료 |
| `helpdesk.ticket.created` | 문의 접수 (운영자 알림을 붙이는 지점) |
| `helpdesk.ticket.answered` | 운영자 답변 (작성자 메일 알림이 여기 붙어 있다) |

## 검증

```bash
DATABASE_URL=postgresql://brick:brick@localhost:5432/brick bash scripts/smoke-helpdesk.sh
```

109개 항목. 특히 다음을 못박습니다.

- 남의 문의가 **404** 로 응답되는가 (403이면 존재가 새어 나간다)
- 남의 목록·상세에 계좌번호·주문번호가 노출되지 않는가
- 비회원 조회 비밀번호가 실제로 검증되는가 (틀리면 404)
- 답변 후 재질문이 `open` 으로 되돌아가는가
- 사이트맵에 비밀글·비공개 게시판·임시 상품이 새지 않는가

설문조사는 따로 확인합니다.

```bash
DATABASE_URL=postgresql://... bash scripts/smoke-poll.sh
```

100개 항목 — 중복 투표(회원·IP), **IP 원문이 저장되지 않는가**, 결과를 숨길 때
득표 수가 응답에 없는가, 남의 설문 선택지로 집계를 오염시킬 수 없는가.

# 판매 리포트

기간별 · 상품별 · 분류별 판매를 봅니다. 관리자 → 쇼핑몰 → 리포트.

## 먼저: 무엇을 매출로 세는지

숫자를 믿기 전에 정의를 알아야 합니다.

**결제된 것만 매출입니다.** 무통장 주문을 걸어놓고 입금하지 않은 것은 세지
않습니다. 시점도 주문일이 아니라 **결제일**입니다.

**순매출 = 받은 돈 − 돌려준 돈.**

```
주문 기준: 주문 결제금액 합계 − 완료된 반품의 환불액
상품 기준: (항목 금액 − 안분된 할인) − 환불액
```

**신청만 하고 아직 입고되지 않은 반품은 빼지 않습니다.** 물건을 받기 전에는
환불되지 않으므로([반품 문서](commerce.md) 참고) 아직 나간 돈이 아닙니다.
반품이 완료되는 시점에 매출에서 빠집니다.

**날짜는 사이트 시간대 기준입니다.** 기본값은 한국 시간(`Asia/Seoul`)이고
`BRICK_TIMEZONE` 으로 바꿉니다. 바꾸면 과거 집계까지 달라지므로 운영을
시작한 뒤에는 건드리지 않는 것이 좋습니다.

## 리포트 종류

### 기간별

일 · 주 · 월 단위로 묶습니다.

| 항목 | 뜻 |
|---|---|
| 총매출 | 결제된 주문 금액 합계 (배송비 포함) |
| 할인 | 쿠폰 + 사용된 포인트 |
| 배송비 | 받은 배송비 |
| 환불 | 완료된 반품으로 나간 돈 |
| 순매출 | 총매출 − 환불 |
| 평균 주문금액 | 순매출 ÷ 주문수 |

### 상품별

어떤 상품이 얼마나 팔렸는지. 판매수량은 **취소·반품된 수량을 뺀** 값입니다.

배송비는 상품별로 나누지 않습니다 — 한 주문에 여러 상품이 들어가면 어느
상품의 배송비인지 정할 수 없습니다. 그래서 **상품별 순매출 합계 + 배송비 =
기간별 순매출**이 됩니다.

주문 단위 할인(쿠폰)은 상품 금액 비중으로 나눠 붙입니다. 반품 환불과 같은
규칙이라 합계가 어긋나지 않습니다.

삭제한 상품의 판매도 남습니다. 상품명은 주문 시점의 값입니다.

### 분류별

`상위로 합치기` 를 켜면 최상위 분류로 묶습니다. 3단 분류를 쓰는 사이트에서
말단 분류만 보면 "의류가 얼마나 팔렸는가"를 알 수 없습니다.

분류를 지정하지 않은 상품은 `(분류 없음)` 으로 묶입니다 — 빼지 않습니다.
합계가 기간별 리포트와 어긋나면 둘 다 믿을 수 없기 때문입니다.

> 상품에 분류를 지정하려면 상품 등록 화면의 **분류** 항목을 쓰세요.
> 분류를 먼저 만들어야 선택지에 나옵니다.

### 요약

같은 길이의 직전 기간과 비교합니다. 8월 1~31일을 보면 7월 2~31일과
비교합니다.

직전 기간의 매출이 0이면 증감률을 표시하지 않습니다 — 0에서 100만원으로
늘어난 것을 "100% 증가"나 "무한 증가"로 쓰면 둘 다 거짓입니다.

## 엑셀로 내보내기

각 리포트의 `CSV 내보내기` 를 누르면 엑셀에서 바로 열리는 파일을 받습니다
(한글이 깨지지 않고, 상품명의 콤마도 필드를 깨뜨리지 않습니다).

API 로 직접 받으려면 `?format=csv` 를 붙입니다:

```bash
curl -b cookies.txt "https://example.com/api/plugins/brick-shop/admin/reports/products?from=2026-08-01&to=2026-08-31&format=csv" -o sales.csv
```

## 자주 겪는 상황

**매출이 실제보다 많아 보입니다**
반품이 완료 처리되지 않았을 수 있습니다. 반품 관리에서 `입고` → `완료` 까지
진행해야 환불이 반영됩니다.

**어제 결제인데 오늘로 잡힙니다**
`BRICK_TIMEZONE` 이 설정과 다를 수 있습니다. 리포트 응답의 `timezone` 값을
확인하세요.

**분류별이 전부 `(분류 없음)` 입니다**
상품에 분류가 지정되지 않았습니다. 상품 등록·수정 화면의 **분류** 항목에서
지정하세요.

**미결제 주문도 세고 싶습니다**
주문 관리 화면의 상태별 건수를 보세요. 리포트는 매출을 보는 화면이므로
결제된 것만 셉니다.

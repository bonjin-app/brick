Brick

파일만 올리면 돌아갑니다. 속은 현대적으로.
Docker 한 줄, 또는 FTP 업로드로 설치하는 오픈소스 CMS.

Next.js · NestJS · PostgreSQL · TypeScript

# Docker — 명령 세 줄
curl -O https://raw.githubusercontent.com/bonjin-app/brick/main/docker-compose.yml
echo "BRICK_SECRET=$(openssl rand -base64 32)" > .env
docker compose up -d

# 또는 FTP 업로드 — 빌드 불필요
# 배포본을 올리고 실행하면 브라우저에서 설치
node server.js

왜 만들었나

PHP CMS의 장점은 언어가 아니라 배포 편의성이었다

오래 살아남은 CMS 들의 공통점은 언어가 좋아서가 아니라, 파일을 올리면 그냥 돌아갔기 때문입니다. 현대 스택은 강력하지만 설치가 어려워졌습니다. Brick은 그 편의성을 되찾는 프로젝트입니다.

📦

설치 방법이 두 가지

Docker는 docker compose up -d 한 줄. FTP는 파일을 올리고 브라우저에서 DB 정보만 입력하면 됩니다.

🔄

마이그레이션은 자동

docker compose pull && up -d 또는 파일 덮어쓰기 후 재시작. DB 스키마는 부팅할 때 스스로 최신으로 맞춥니다.

🧩

ZIP 업로드로 확장

워드프레스와 똑같습니다. 관리자에서 plugin.zip / theme.zip을 올리면 설치됩니다. 서버에서 빌드하지 않습니다.

🎨

테마는 빌드가 없다

테마는 런타임 템플릿(HTML)입니다. React를 몰라도 만들 수 있고, 업로드하면 즉시 반영됩니다.

⚡

PostgreSQL 하나면 충분

Redis 없이 동작합니다. 캐시·큐·락을 PostgreSQL로 구현하고, Redis는 규모가 커질 때 켜는 선택지입니다.

🔍

SEO는 설계 전제

테마가 문서 전체를 소유하는 SSR입니다. 검색엔진은 완성된 HTML을 그대로 받습니다.

🧪

실제 서버로 검증

E2E 스모크 2,072개가 실제 PostgreSQL과 실제 서버 프로세스를 띄워 돕니다. 재고 동시성·금액 위조·저장형 XSS·로그인 CSRF처럼 틀리면 돈이나 계정을 잃는 경로를 항목으로 못박아 두었습니다.

📐

결정의 이유가 남아 있다

설계 결정 49건을 ADR로 기록했습니다. "왜 이렇게 되어 있나"에 답할 수 있는 코드가 오래 삽니다.

Brick은 순수 PHP 호스팅(Node 없음)에서는 동작하지 않습니다 — Node 런타임이 필요합니다. Docker, 또는 Node.js를 지원하는 호스팅(cPanel/Plesk의 "Node.js App", VPS)이 필요합니다. 그 환경이라면 FTP로 올려서 브라우저에서 설치하는 방식이 동작합니다.

구조

사용자에게는 앱 컨테이너 하나와 PostgreSQL 하나로 보입니다.

              사용자 / 검색엔진
                     │  :3000  (유일한 공개 포트)
              ┌──────▼──────┐
              │   Next.js   │  SSR · ISR · 관리자 UI
              └──────┬──────┘
                     │  :3001  (내부 전용)
              ┌──────▼──────────────────────┐
              │      Brick Runtime          │
              │   NestJS · 단일 프로세스     │
              │  ┌───────────────────────┐  │
              │  │ Core    HookBus       │  │
              │  │ Plugins 동적 로드      │  │
              │  │ Themes  런타임 템플릿  │  │
              │  └───────────────────────┘  │
              └──────┬──────────────────────┘
                     │
                PostgreSQL     ← 유일한 필수 의존성
         (Redis · S3는 선택 — 없으면 PG 기반 기본 구현)

확장 만들기

플러그인은 사전 빌드된 JS, 테마는 HTML. 둘 다 ZIP으로 배포합니다.

  1. 플러그인 = 라우트 + 블록 + 훅definePlugin((ctx) => { ctx.registerRoute(...); ctx.registerBlock(...) }) 하나로 REST API와 페이지 빌더 블록을 등록합니다.
  2. 자기 테이블을 소유한다플러그인에 migrations/*.sql을 담으면 활성화 시점에 자동 적용됩니다. 코어 스키마를 건드리지 않습니다.
  3. 테마는 템플릿 문법 4개면 끝{{ 변수 }}, {{{ HTML }}}, {{#if}}, {{#each}}. 로직이 필요하면 블록으로 만듭니다.
  4. 업로드하면 즉시 동작서버 재시작도, 빌드도 없습니다. 관리자에서 ZIP을 올리고 활성화만 누르면 됩니다.
